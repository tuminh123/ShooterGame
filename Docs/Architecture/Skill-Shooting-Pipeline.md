# Skill and shooting pipeline

> **Trạng thái:** ✅ Hiện hành · Kiểm tra với code: 2026-11-27 (đạn sprite + vệt, impact particle, VFX trạng thái — xem [Vfx-2D-Plan](Vfx-2D-Plan.md)).

See [Skill Run Progression](Skill-Run-Progression.md) for the current model.

SkillDataSO stores complete per-level behavior data and a list of behavior types
(`SkillBehaviourType[]`). `SkillFactory` creates each behavior from one switch and reuses it through a per-type `Pool<T>`;
the same enum pairs the level data with the behavior. Abstract Skill supplies default
lifecycle methods. SkillRuntime activates only behaviors with data at its level.
There is no ShootingLevelTable, root stat bonus, string behavior ID or wrapper entry.

ShootingData owns the shooter/movement/projectile settings for a single level.
ShootingSkill snapshots a volley, uses shared shooting/movement services and gives
projectiles independent damage/effect snapshots. The existing projectile/VFX
pipeline below remains in use.

## VFX child lifecycle

- `CombatAssets` has two shared shells: `ProjectileView.prefab` (formerly HolyBolt) and `EffectView.prefab` (formerly HolyImpact). Their original GUIDs are preserved. Bullet entries contain type, child visual prefab, impact effect and a per-type hit radius/offset; effect entries contain type and child visual prefab. Skills select BulletType; every skill/level using a type shares its catalog hitbox. `Tools > Shooter Game > Hitbox Editor` edits these entries independently. There are no catalog sprite, tint or width overrides.
- **Bắn đạn (2026-11-27):** `ProjectileSystem.SpawnBullet` thuê vỏ (OnEnable của vỏ không làm gì) rồi gọi ngay `ProjectileView.Launch`: gán thông số, thuê visual con theo BulletType với vị trí/góc thế giới đúng, đăng ký movement và ProjectileSystem. Không dùng lambda `beforeActivate`; `Launch` lỗi thì vỏ được trả ngay. Release returns the child before the shell. Camera culling combines child Renderer bounds (renderer lấy vào một `List` dùng lại, không cấp phát mảng mỗi viên). ProjectileView does not control Animator, ParticleSystem or TrailRenderer playback; the visual prefab owns presentation. Author it facing local +X and configure color, size, animation and materials inside the prefab.
- The catalog maps Holy, Fire, Ice and Poison bullets to matching impact IDs; HolyImpact keeps serialized ID 1. FireImpact, IceImpact, PoisonImpact, LightningImpact and WindImpact have distinct entries. Added sample visuals currently reuse the original artwork with prefab-authored tints; replace these child prefabs with your own VFX. Prewarm prepares both shells and their children.

- Scripts are grouped in `Combat/Vfx`. **Phát impact (2026-11-27):** `CombatVfx.Spawn` thuê vỏ `EffectView` (OnEnable không làm gì) rồi gọi `EffectView.Play(pools, visualPrefab)`: gắn visual con theo EffectType và gọi `IEffectVisual.Play()`. Mỗi LateTick, `CombatVfx` hỏi `Advance(dt)`; trả về true (phát xong) thì trả visual con rồi trả vỏ (swap-remove trong `List`). Không còn event `Completed`, `playbackVersion` hay lambda: không có callback trễ nào trỏ sang lượt pool đã đổi chủ. There is no fixed duration or lifetime timer on the shell.
- `ParticleEffectVisual` implements `IEffectVisual` directly. It plays the root ParticleSystem with children and waits for `IsAlive(true)` to become false, including delayed emission and remaining child particles. These pooled impact effects are forced to one-shot, gameplay-scaled playback with auto-destroy/disable disabled on every child system.
- `Advance` trả true một lần khi phát xong tự nhiên, false khi đang phát, đang pause (`dt = 0`) hoặc ở frame vừa bật. `StopAndReset` hủy lượt phát. Shell disable stops playback without reparenting children inside Unity's hierarchy callbacks.
- `EffectVisual`, `AnimationEffectVisual` (clip qua PlayableGraph) và `ObjectEffectVisual` (sprite tĩnh theo thời gian) đã bị xóa (2026-11-27): không prefab nào còn dùng. `IEffectVisual` được giữ để thêm cách hiển thị khác sau này (ví dụ sprite động) mà không sửa `EffectView`/`CombatVfx`.
- **Giới hạn impact (2026-11-27):** `CombatVfx.Spawn` bỏ qua VFX mới khi vượt `CombatAssetsSO.maxNewEffectsPerFrame` (8) hoặc `maxActiveEffects` (64); chỉ là hình nên gameplay không đổi. Xem [Vfx-2D-Plan](Vfx-2D-Plan.md).
- **Hiện tại (2026-11-27):** 4 đạn là **sprite + vệt** (`Vfx/Prefabs/Bullets`: sprite cũ + con `Trail` là `TrailRenderer`); 4 impact là **particle** (`Vfx/Prefabs/Impacts`); mọi material/texture/shader nằm trong `Assets/_Project/Vfx/`. Gốc prefab đạn có `ParticleProjectileVisual`: bật/tắt thì xóa vệt (và hạt nếu có), nên đạn tái dùng từ pool không kéo vệt từ chỗ cũ. Gốc prefab impact có `ParticleEffectVisual`. `ProjectileView` không cần biết visual là sprite hay particle.
- Prefab impact sprite cũ (`Prefabs/VisualEffect`), đạn particle 3D, thư viện VFX dựng lại, tool chuyển đổi và 2 pack Hovl Studio / AllIn1VfxToolkit đã bị xóa (2026-11-27). Prefab sprite đạn cũ được khôi phục và chuyển vào `Vfx/Prefabs/Bullets` (giữ GUID).
- `CombatVfx` and `CombatAssetsSO` select child prefabs. A visual prefab must have an `IEffectVisual` implementation on its root. `CombatVfx.Spawn` rents the shell, then `EffectView.Play` attaches the visual with its authored local transform and starts playback. Bullets are spawned and released by `ProjectileSystem` (it owns the whole bullet lifecycle). Neither needs to distinguish animation from particles.

## Gameplay effects

- Sprite feedback belongs to `CharacterView` for both player and enemy. `CharacterControllerBase` implements the separate `ICharacterFeedbackSource` interface and emits hit/status events; the view subscribes for the current spawn and selects colors with a switch. `EffectSystem` reports successful status application/removal through the character to its controller. Poison is purple, burn orange and slow ice blue. Concurrent statuses blend together; multiple instances of the same status keep its color until the last instance is removed. Refreshing an existing timed effect does not add another color instance.
- **VFX trạng thái (2026-11-27):** ngoài màu, `CharacterFeedback` bật một VFX lặp trên nhân vật khi trạng thái bắt đầu và trả về pool khi trạng thái kết thúc, nhân vật chết, phát kết quả hoặc bị thu hồi. Prefab gán trên `Character.prefab` (`Poison Vfx`, `Burn Vfx`, `Slow Vfx`, ngay dưới các màu), trống = chỉ đổi màu. VFX **không làm con của vỏ** (trạng thái có thể đổi ngay trong OnEnable/OnDisable của vỏ, lúc Unity cấm đổi cha) mà bám theo `HitPosition` ở `CharacterView.LateTickFrame`. Controller đã đếm số nguồn mỗi loại nên hai nguồn cháy không tắt nhầm VFX. Prewarm: `additionalPrefabs` trong `PoolPrewarmSettings`.
- `CharacterView` retains each renderer's authored color and alpha. Accepted damage, including shield-only damage and direct HP loss, applies a brief 22% blend toward white over the current status tint. Expiry restores the current status color. Disable cancels the flash, while death/despawn/destroy remove listeners, cancel delayed work and restore original colors. The shared `Character.prefab` exposes tint colors, blend strengths and hit duration. `PlayerSystem` no longer owns sprite colors or flash tasks; `EnemyCombatFeedback` only handles sprite death playback and Animator restoration.

- `ShootingSkill` stores `[SerializeReference] List<IGameplayEffect>`. Expand Effects, add an entry and choose `SlowEffect`, `BurnEffect` or `PoisonEffect` in the skill inspector. Each selected object contains configuration only.
- `ProjectileSpawnData` carries those configurations plus the source effect-hit stat. The bullet keeps no skill/source-character reference. On an accepted damage hit it calls `EffectSystem.Apply(configuration, target, sourceTeam, effectHit)` directly; there is no combat event hub. Other hit producers, such as a future area skill, use the same method.
- `EffectSystem` checks spawn identity, team, chance and resistance, then rents an `EffectRuntime`. Reapplying the same timed configuration object to the same target refreshes duration without creating another runtime or resetting periodic cadence. Separate configuration entries remain independent. Each slow runtime owns a percentage MoveSpeed modifier; slows add together and final speed is clamped at zero.
- Configuration types derive from `GameplayEffectData`; running behaviors derive from `EffectRuntime`, which owns `Apply`, `Tick` and `Remove`. Slow-specific modifier ownership lives in `SlowEffectRuntime`; damage behavior lives in `DamageOverTimeEffectRuntime`. Each runtime stores its own remaining duration and interval phase. EffectSystem.Tick calculates due ticks, including the final tick at expiry and all due ticks within a long frame; runtime Tick applies the resulting count.
- `EffectRuntimePool` is a plain C# pool created by `CombatManager`: one `Stack<T>` per runtime type, rented with typed methods (`RentSlow`, `RentDamageOverTime`). `GamePrewarm` preallocates the counts from `PoolPrewarmSettings`; pools grow when necessary. Burn and poison can reuse the same runtime type while remaining separate configurations.
- `CombatManager` ticks `EffectSystem` (effect → skill → projectile order); it advances a versioned snapshot of runtime effects on the main thread, uses dictionaries to find reapplications and per-target groups for pause/cleanup, and removes runtimes by swapping the final list element. Group lists are reused. Returns are deferred until the current effect operation finishes, so synchronous damage/stat callbacks cannot recycle a runtime while it is still executing. Removal clears modifiers; reset clears target/configuration references before returning to the pool.
- `CharacterView` asks Combat (through the temporary `ICombatOwners` contract) to clear effects on death, destruction and `ClearSpawn`, and pauses each target's duration and tick accumulation on temporary disable. `FrostAuraSkill` applies a maintained `SlowEffectRuntime` on entry and removes its versioned handle on exit, pause, data replacement or disposal. Maintained applications create independent runtimes even for a shared configuration; aura slow keeps its guaranteed application behavior. Target identity and handle versions prevent effects from crossing pooled lifetimes.
- Gameplay duration is independent of VFX lifetime. Periodic damage is a fixed `damagePerTick` chosen in each skill and goes through `ReceiveDamage`, including shield absorption. Sample burn uses 2 damage each second for 3 seconds, poison uses 2.5 each second for 4 seconds, and slow reduces speed by 30% for 2 seconds. These periodic values match the old multiplier-based assets at source damage 10; future character damage changes no longer scale them implicitly. Application chance still considers effect hit/resistance when enabled.
- Sample skill YAML now embeds managed effect configurations. The old effect SO assets/classes remain as unused source data; they are no longer applied by the gameplay pipeline.
- Adding an effect requires a serializable configuration and runtime behavior. Register a pool in `GameSceneInstaller` and `EffectRuntimePool` only when introducing a new runtime type. The inspector discovers new concrete serializable configurations automatically.

The previous `ShootingDataSO`, pattern assets, per-projectile assets, pattern/flight/hit factories and separate projectile runtime are removed. The unused homing prefab is also removed; homing uses the same bullet shell.

Skill upgrades, permanent skill progression and selection UI are not implemented. Character/EXP level progression remains in the existing level services.
